**先说清楚这一页是什么**：清小搭是**清华大学自己的** AI 助手，不是本站的功能。
本站不代它提供入口、不调它的接口，只负责讲清楚它是干什么的、什么时候该用它、
想自己搭智能体该看哪份文档 —— **剩下的你自己点过去**。

它和[站内问答](/ask/)是两件事，分工见下面那张表。

## 它是什么

一句话：**清小搭是学校官方的学生 AI 助手**，问答的根据是学校自己的知识库，不是网上搜来的东西。

- **2024 年 8 月 14 日上线**，也就是 2024 级本科新生开学第一天，最早以微信小程序的形式提供 24 小时在线服务。
- 用学校的话说，它依托**清华自研的大模型和知识增强生成技术**，做的是「智能问答 + 智能伴学」。
- 技术文档站的说法是：底座是清华团队自研的**千亿参数大模型**，算法服务基于 [UltraRAG](https://github.com/OpenBMB/UltraRAG) 框架，实现了知识库问答、智能摘录、工具调用和智能体等功能。
- **个人隐私敏感数据由学校信息办数据中台建设、存储和管理**，学校官方的说法是师生信息「不出校」。这一点和本站无关，但你如果在意数据流向，这是官方给的承诺。

## 你现在能用吗

**这是最容易过时、也最该自己确认的一件事。**

- [学生学习与发展指导中心的页面](https://learning.tsinghua.edu.cn/xxyfzxm/aitown/qxd.htm)至今写着
  「**目前处于试运行阶段，仅面向 2024 级本科生开放**」。
- 清小搭站内的《用户协议》也把服务对象写成「**清华大学 2024 级本科新生或被清华大学允许的试用或测试用户**」，
  并写明账号**仅限本人使用、在清华就学期间享有使用权**，不得转让、借用、售卖或授权给第三方。
- 但官方动态页显示：2026 年 4 月起清小搭**面向全体教职工开放**（小程序 + Web 双端，中英双语）；
  2026 年 5 月面向国际学生的版本进入试运行，当时说「预计秋季学期正式上线」。

也就是说，**文本上它还写着限定范围，实际上早就扩到了教职工和国际学生**。
别拿任何页面的「仅面向 XX 开放」当准——包括这一页。最可靠的办法是直接去登录一次。

## 它和站内问答的分工

两边都是「问一句答一段」，但**依据完全不同，用错地方会拿到错的答案**。

| | [站内问答](/ask/)（本站） | 清小搭（学校） |
| --- | --- | --- |
| 谁做的 | 本站维护者 | 清华大学 |
| 依据什么 | 站内 60 多篇经验帖 | 学校知识库（官方文档、常用域名、校内公众号） |
| 答的是 | 学长学姐踩过的坑 | 学校的官方口径与事务办理 |
| 站里没写的 | 直接拒答，不编 | 不适用（它答的是学校的事） |
| 给出处吗 | 每句标到具体文章与章节 | 不标到本站 |
| 入口 | 就在本站 | 要登录，自己过去 |

**简单说：想知道「规定是什么、手续去哪办」，去清小搭；想知道「实际会踩什么坑、别人怎么过来的」，留在本站。**
两边的结论冲突时，**以学校官方为准**——这也是本站[免责声明](/start/disclaimer/)里的原则。

:::caution[清小搭也是 AI，别把它当红头文件]
它的回答同样是模型生成的。本站整理[清小搭问答精选](/guides/frequent-questions/)时就发现，
不少条目**没有日期、年份混杂**，制度细节也没法逐条对上官方文件。

所以它是一条**比网上搜索靠谱得多的线索**，但不是依据：办事、交材料之前，
仍以**官方通知、院系口径和现场公示**为准。这一点和本站问答是同一种诚实——**都别当文件用**。
:::

## 想自己搭一个智能体

以上是给使用者的。下面这段给**想自己动手搭智能体**的同学——比如参加[清华大学人工智能创新大赛](https://www.xiaoda.tsinghua.edu.cn/m/competition)，
或者只是想在智能体广场放一个自己的东西。

大赛**每年一届**（2026 年那届的赛期是 6 月至 9 月，报名 7 月底截止），具体时间以官方通知为准；
非赛期也照样可以自己搭了上架，不必等比赛。

### 三条路，按投入从低到高

1. **在平台上直接搭。** 用清小搭内置的智能体共创平台（BISHENG 是清小搭侧用于智能体构建和配置的平台），
   或者用扣子（Coze）、扣子开源版（产品界面里叫 **Coze Studio**，大赛 FAQ 里写作「OpenCoze」）、
   智谱清言等外部平台搭好，再通过「平台接入」同步到清小搭。智谱清言支持 OAuth 与 API Key 两种授权方式。
   *代价*：官方 FAQ 明确提醒，第三方平台会持续更新，平台**无法保证所有 Coze 接口模式和版本都兼容**，
   对话流模式、OAuth 未授权插件是常见的坑。
2. **上传 Skill 技能包。** 打包成标准 ZIP 上传，让别的智能体调用你的技能。
   官方要求：README 里写清**运行环境、依赖项、版本和配置方法**；关键依赖要给替代方案或异常提示；
   遵循权限最小化和数据最小化；依赖来源要清晰、稳定、合法合规。
3. **自己写代码，按 OpenAI 兼容标准协议接入。** 最通用，也最可控。下面是它的契约。

### 第 3 条路：最小接入契约

核心思路一句话：**把你的服务写成一个「长得像 OpenAI」的 HTTP 服务，网关由清小搭提供，你不用管。**
官方接入指南的原话是「你不需要实现平台网关的任何东西」。

必须实现两个端点：

| 端点 | 必须 | 用途 |
| --- | --- | --- |
| `POST {baseUrl}/chat/completions` | ✅ 必须 | 对话（流式 SSE + 非流式 JSON 都要） |
| `GET {baseUrl}/models` | 🟡 强烈建议 | 连通性与凭证校验（不实现也行，平台会用最小对话兜底） |

硬性要求（任何一条不满足，平台的探测就不通过）：

1. HTTP/HTTPS，`Content-Type: application/json`；流式响应用 `text/event-stream`。
2. 支持 `Authorization: Bearer <credential>` 鉴权（或 `x-api-key` / 自定义请求头）；**无效凭证返回 `401`**。
3. 请求与响应都按 OpenAI 风格（`messages` / `choices` 那一套）。
4. `stream: true` 时返回 SSE，**以 `data: [DONE]` 结尾**。
5. `finish_reason` 只用官方那五个值之一。
6. 返回 `usage`（token 用量）字段，统计不了就填 `0`。

:::tip[`baseUrl` 填到哪个位置]
填到**版本段为止**，例如 `https://your.host/v1`。网关会自己拼 `baseUrl + /chat/completions`，
**不做 `/v1` 去重** —— 所以你多写或少写一个 `/v1`，探测都会失败。
:::

进阶可选能力（不影响纯文本对话接入）：音频输入 `input_audio`、文件输入 `file`（pdf/word 等）、
文件产物输出 `x_soda.attachments`（返回 PDF/PPT/Word）。

### 上架流程：四步

1. **平台信息** —— 选「标准协议接入」，填 API 地址与 API 密钥；需要自定义鉴权头时展开高级配置。
2. **测试验证** —— 平台自动探测 `/models` 与 `/chat/completions`，给出四项检查结果；通过后可以直接试聊。
3. **完善信息** —— 头像、智能体名称、描述、开场白、上架分类、引导问题。
4. **审核上线** —— 提交审核，通过后上架智能体广场。

**第二步出红叉怎么排查**：`凭证校验` 对应密钥或鉴权方式；`发起最小对话` 对应 `/chat/completions`；
`校验响应格式` 对应响应结构不像 OpenAI。对着上面那六条硬性要求逐条核对，通常就在里面。

### 一条不能碰的红线

官方 FAQ 写得很明确：**不统一开放课程表、借阅记录等涉及个人隐私或校内敏感信息的数据接口**，
也**不得通过绕过权限的方式访问校内私有数据**。作品需要数据能力时，只能用公开数据、
已获授权的数据、安全可访问的外部数据库或 MCP 服务，并做好脱敏与最小化采集。

:::danger[本站的态度]
「绕开权限拿校内数据」这件事，本站不写教程、不提供思路、不链接任何相关工具。
这不是技术问题，是会不会出事的问题。
:::
