**Markdown 的价值不是"好看"，而是"内容和格式分开"。** 你只写内容，标题、列表、加粗用几个符号表示，剩下的交给渲染工具。

它最大的好处常常在很久以后才体现出来：**它是纯文本，十年后还能打开。** 而某个 App 的私有格式，等这个 App 停止服务，你的笔记就一起没了。

## 为什么现在就该学

| 场景 | 具体会发生什么 |
| --- | --- |
| **上课记笔记** | 打字比手写快，但格式乱、公式没法写——Markdown 让笔记结构清晰、可全文搜索。 |
| **实验报告与作业草稿** | 先用 Markdown 把思路写顺，再决定要不要排成正式格式，比直接在 Word 里改来改去快。 |
| **科研** | 组会记录、实验日志、代码说明（README）几乎都默认用 Markdown 写。 |
| **实习** | 技术文档、需求说明、Issue 描述、代码仓库里的说明文件，都是 Markdown。 |
| **投稿本站** | 本站在 GitHub 上协作，文章就是 Markdown 文件，见[怎么贡献一篇经验帖](/contribute/)。 |

## 马上能做的

- [ ] 装一个能实时预览 Markdown 的编辑器（免费的就行，例如 [VS Code](https://code.visualstudio.com/docs)），新建一个 `.md` 文件，把下面那张语法表全敲一遍。
- [ ] 把今天某一门课的笔记，用 Markdown 重写一遍，标题层级只用到两级。
- [ ] 定下一条规矩：**每门课一个文件**，文件名用「课程名 + 学期」，不要按日期建几十个小文件。
- [ ] 在笔记文件的最上面加三行：课程名、老师布置的考核方式、本周要交的东西。
- [ ] 把笔记目录放进[校内云盘](https://cloud.tsinghua.edu.cn/)，或者用一个私有 Git 仓库同步（做法见 [Git 那一篇](/skills/git-and-gitlab/)）。

## 语法最小集

真的只需要这些。左边是写法，右边是效果：

| 写法 | 效果 |
| --- | --- |
| `# 标题` / `## 二级` | 标题层级，**最多用到三级**，再深就该拆文件了 |
| `**加粗**` / `*斜体*` | 强调。一段里不要超过两处，否则等于没强调 |
| `- 条目` | 无序列表 |
| `1. 条目` | 有序列表 |
| `> 引用` | 引用别人的话、贴一段原文 |
| `` `代码` `` | 行内代码，例如 `git status` |
| 三个反引号包起来 | 代码块，可以标注语言 |
| `[文字](链接)` | 链接 |
| `![说明](图片路径)` | 图片，方括号里是图片说明，**不要留空** |
| `\| 表格 \| 表格 \|` | 表格，适合对比和参数说明 |
| `---` | 分隔线，用来切分大段落 |

:::tip["语法没生效"最常见的原因：少了空行]
标题、列表、表格、代码块的前后**都要有一个空行**。这是初学者最常遇到的坑：符号都对，就是渲染不出来，回去补个空行就好了。
:::

:::caution[Markdown 不擅长什么]
它没有精确的页面控制：**页码、页边距、页眉页脚、图注编号这些都不是它的强项**。需要严格排版时，用 [LaTeX](/skills/latex-and-overleaf/) 或 Word，Markdown 只负责把内容写出来。用 [Pandoc](https://pandoc.org/) 可以把 Markdown 转成 PDF、Word 等多种格式，但转换后的细节仍需要自己检查。
:::

## 笔记工具怎么选

不要问"哪个工具最好"，问**这五个问题**：

1. **能不能导出开放格式？**（Markdown、纯文本、PDF）导出不了的工具，等于把笔记质押给它。
2. **离线能不能用？** 教室里网不好是常态。
3. **能不能全文搜索？** 包括公式和图片里的文字。
4. **公式好不好写？** 理工科的笔记绕不开公式。
5. **五年后它还打得开吗？** 这个问题的答案通常取决于第 1 条。

按形态分，主流选择就三类：

| 形态 | 适合谁 | 主要代价 |
| --- | --- | --- |
| **纯文本 / Markdown 文件 + 编辑器** | 想长期保存、愿意自己管文件的人 | 同步和搜索要自己配 |
| **双链笔记类工具** | 笔记量大、喜欢互相链接的人 | 数据在工具的库里，导出格式可能不完美 |
| **云端块编辑器** | 以记录为主、不想折腾的人 | 依赖网络和账号，导出常带一堆格式残留 |

:::note[不要为了选工具花掉一周]
随便选一个能导出 Markdown 的，先用一个学期。**换工具的成本远低于"一直在选工具"的成本**，而且笔记的骨架（课程、章节、日期）在任何工具里都能迁移。
:::

## 上课记笔记的实际做法

目标不是"记全"，而是**课后再看能想起来老师讲了什么**。具体做法：

1. **课前 3 分钟**：新建当天的文件，写好标题和日期，把这节课的课件或大纲扫一眼。
2. **上课时只记三类内容**：
   - 老师讲了但课件上没有的（例题、口头强调、补充说明）；
   - 你**当场没听懂**的地方（写个问号就行，别停下来纠结）；
   - 老师明确说的考核相关内容。
3. **不要抄课件**。课件本来就能下载，抄一遍只是把时间花在搬运上。
4. **课后 10 分钟**：在文件末尾写三行——这节课讲了什么、我还欠什么、下次课前要补什么。**这三行的价值超过课上记的所有内容。**
5. **每周一次**：把本周的笔记里带问号的地方过一遍，能自己查明白的就查，查不明白的攒着问老师或同学。
6. **每月一次**：建一个索引文件，按课程列出笔记文件的位置。

:::tip[公式和图怎么办]
公式用 LaTeX 写法（行内用 `$...$`）记，大多数工具都能渲染。图不要用截图糊上去，**画个示意图或者写文字描述**更耐用——因为截图里的信息你永远搜不到。
:::

## 导出与备份

这部分最容易被忽略，但它决定了你的笔记两年后还在不在。

- **图片单独放一个目录**（例如 `assets/`），文件名用英文或拼音加日期。**不要把图片复制进文档正文**，也不要用聊天软件里的临时图片链接。
- **导出**用 [Pandoc](https://pandoc.org/) 可以从 Markdown 生成 PDF、Word、HTML。导出后**一定要打开检查一遍**：公式、表格、图片是最容易出问题的三处。
- **备份至少三份**：本机一份、云盘一份（如[校内云盘](https://cloud.tsinghua.edu.cn/)）、移动硬盘或私有仓库一份。三份里至少有一份是**离线**的。
- **不要用"只存在于一个 App 里"的笔记**。四年下来，笔记是你最舍不得丢的东西之一。

:::danger[笔记里不要写敏感信息]
课堂讨论中涉及的个人信息、未公开的研究数据、他人的隐私，不要写进会同步到云端的笔记里。笔记是记录，不是档案库。
:::

## 常见坑

:::caution
- **只记不回顾。** 笔记的价值在第二次打开时产生，不回顾的笔记等于没记。
- **过度分类。** 建了二十个文件夹和一堆标签，结果每次记笔记先花五分钟想"这该放哪"。**按课程分就够了。**
- **一个知识点开一个新文件。** 文件越碎越找不回来。
- **把正式作业用 Markdown 交。** 除非老师明确允许，否则正式文件请按课程要求的格式提交。
- **依赖某一个工具的特色语法。** 双链、特殊标记这类语法一换工具就失效，重要内容用最朴素的标准语法。
- **图片粘贴后没落地。** 很多编辑器插入的是临时链接，文档一分享图片就全挂。
- **笔记和课件混在一起。** 课件按老师给的原件存，笔记写你自己的理解，两者分开。
:::

## 延伸阅读

- [Markdown 指南](https://www.markdownguide.org/) —— 语法速查。**不需要通读**，把「基础语法」那一页过一遍就够用了。
- [Pandoc](https://pandoc.org/) —— Markdown 与 Word、PDF、HTML 之间互转的万能工具，导出作业草稿和分享文档时非常有用。

- [MDN Web 文档（中文）](https://developer.mozilla.org/zh-CN/) —— 如果你想搞清楚 Markdown 背后的 HTML 到底怎么渲染，或者以后要写网页，这是最可靠的中文参考。
