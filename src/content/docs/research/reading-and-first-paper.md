:::danger[本文尚未核实，不得作为投稿或写作决定的依据]
这篇**分成两半**：一半是**不依赖任何具体政策的方法**（怎么找、怎么读、怎么复现、怎么和导师讨论），可以放心看；另一半是**必须由亲历者核实的规则类事实**（格式、署名、投稿流程等），**只有清单，没有答案**，而且没有写任何具体期刊、会议或学校的政策。

**不要用本文判断"该投哪里""署名怎么排""格式怎么改"**——这些答案只在课程要求、接收方的正式说明和你的导师那里。
:::

写第一篇论文真正的难点往往不是"不会写"，而是**不知道该按什么规则写、卡在哪一步该问谁**。规则类信息换个课程、换个方向、换个接收方就完全不同，写死在文章里只会误导人。

所以这篇的结构和[保研（推研）全流程：待核实的骨架](/research/graduate-recommendation/)一致：**方法部分写清楚，规则部分只列清单**。

## 这篇文章现在是什么状态

- **状态**：未核实骨架（frontmatter 里 `status: draft`，且没有核对日期）。
- **谁来填**：近一两年真正完成过一篇论文（课程论文、毕设、投出去的工作均可）的同学，填的时候请注明**适用年份 + 方向/课程 + 接收方类型**。
- **读者怎么用**：方法部分当参考；规则部分当**提问清单**，拿去问导师、助教或课程负责老师。
- **什么时候能改状态**：只有当涉及格式、署名、投稿与规范的关键条目都有人核实过、并写明了适用条件，才谈得上把 `status` 改成 `stable`。

## 这篇文章不做什么

- **不写任何具体期刊、会议、出版社或它们的要求**。不编造名称，也不替读者假设"投哪里"。
- **不写模板、字数、格式条款与引用标准编号**。要求写在哪份文件里，就照那份文件办。
- **不写"几分能中""多久能录用"这类经验数字**，也不比较任何方向"好不好发"。
- **不写任何规避学术规范的"技巧"**。查重、署名、AI 使用的边界一律按课程与接收方的正式规定执行。

## 环节概览：只写"有哪些环节"

从"读文献"到"第一篇论文"通常围绕这条线展开，但**具体到你，环节多少与先后关系都可能不同**（课程论文没有投稿环节，合作项目里写作也可能不由你主导）。

| 环节 | 这一步在做什么 | 你需要在这里确认的事 |
| --- | --- | --- |
| **①② 缩范围、找文献** | 从宽泛方向收敛到一个能做完的问题，并找到代表性工作与综述 | 导师对范围的期待、该用哪些检索渠道 |
| **③ 读文献** | 判断每篇做了什么、怎么做的、多可信 | 读到什么程度算够 |
| **④ 复现与记录** | 让结果在你手上跑起来，并留下过程痕迹 | 环境与数据要求、记录形式 |
| **⑤ 定贡献** | 明确自己要说的一句话是什么 | 这个贡献是否值得写、导师是否认可 |
| **⑥⑦ 写作、提交与收尾** | 组织成文、按反馈改，按接收方要求提交并归档 | 格式要求、导师的节奏、提交流程与作者信息 |

**这张表只用来定位"哪一步该问谁"，不是时间线。**

### 材料清单（只有类别，没有格式要求）

一篇工作通常涉及：**文献记录类**（参考文献库、阅读笔记）、**过程类**（实验记录、代码与配置、数据与版本记录）、**成文类**（正文、图表、补充材料）、**声明类**（作者贡献、致谢、利益冲突、AI 使用说明）、**提交类**（接收方要求的表单与格式文件）。**过程材料比正文更难补**——代码版本、数据来源、失败的尝试、和导师讨论的结论，当时不记，三个月后基本找不回。代码版本管理见 [Git 与 GitLab](/skills/git-and-gitlab/)，阅读笔记见 [Markdown 与笔记](/skills/markdown-and-notes/)。

## 方法部分：不依赖具体政策的做法

### 怎么找到一篇论文

1. **从综述入手**。先找一篇该方向的综述类文章，它的参考文献列表本身就是地图。
2. **用图书馆的检索渠道**。数据库入口是[图书馆](https://lib.tsinghua.edu.cn/)；校外访问方式以图书馆说明为准（一般需要 [WebVPN](https://webvpn.tsinghua.edu.cn/)）。
3. **顺着引用链走，并迭代关键词**。往前看关键工作引用了谁，往后看谁引用了它；先用你脑子里的词搜一轮，从结果里抄下这个领域真正在用的术语再搜一轮——**术语对了，检索质量会立刻变好**。
4. **直接问人**。"这个方向必读的三篇是什么"，比自己瞎试快得多。

用文献管理工具把条目和笔记绑在一起，见[文献管理工具](/skills/reference-manager/)（工具本身可用 [Zotero](https://www.zotero.org/)）。

### 怎么读一篇论文

不要从第一页读到最后一句，**按投入产出比分三轮**：

1. **第一轮：标题、摘要、图表、结论。** 目标只有一个——判断**这篇和我的问题有没有关系**。多数论文到这一轮就可以放下。
2. **第二轮：方法、实验设置、结果。** 把**"他们做了什么、凭什么这么说"**说清楚；看不懂的公式先记下来，别卡住。
3. **第三轮：复现细节。** 只有真的要复现或对比时，才逐段读方法与附录，把超参数、数据划分、评价口径抄进笔记。

**每读一篇写三句话**：它做了什么 / 怎么做的 / 我能用在哪。写不出来，说明还没读懂，或者它其实不重要。

### 怎么复现

- **先跑通最小的那一份**：示例、小数据集、默认配置。**先让它动起来，再谈改。**
- **记录环境**：依赖版本、随机种子、数据版本。**"结果对不上"最常见的原因是环境不同**，而不是代码有问题。
- **一次只改一个变量**，并留一份"失败记录"：哪条路走不通、报了什么错。这份记录在写"局限"和下次做实验时都用得上。
- **对不上先假设是自己错了**，再去查文档或问作者；确实复现不了就如实写，**不要为了"看起来一致"去调参凑数**。

### 怎么写、怎么和导师讨论

**写作三条**：先写图表和结论、再写正文（贡献说不清就是还没定型）；每段主题句放第一句；先把内容写出来，最后再管格式——工具方面见 [LaTeX 与 Overleaf](/skills/latex-and-overleaf/)（入门材料可用 [Overleaf 学习文档](https://www.overleaf.com/learn)）。

**讨论四条**：带着具体问题去，把选项和各自的代价一起列出来；**定期同步进展**，哪怕只有三行字——"我卡在这里、试过 A 和 B"是合格的汇报；动笔前先对一次"一句话贡献"；**提前问清署名与投稿规则**，不要等到提交前一天。

学术规范与引用、AI 使用的边界见[作业、引用与 AI：学术规范的边界](/academics/academic-integrity/)；进组与找导师的做法见[怎么进实验室做科研](/research/finding-a-lab/)。

## 需要核实的事实清单

下面每一条都要由亲历者填写，**每条请写明"适用年份 + 方向/课程 + 接收方类型"**。查不到就保持 `- [ ]`，不要猜。

- [ ] **要填什么**：课程论文 / 毕设 / 投稿这三类场景分别适用哪份要求文件（谁发的、在哪能找到）。**去哪查**：课程大纲、院系教务与接收方的正式说明（链接待补）。
- [ ] **要填什么**：正文的格式要求（模板、篇幅、字体字号、页边距、图表编号方式、语言要求）。**去哪查**：课程或接收方提供的模板与说明（链接待补）。
- [ ] **要填什么**：引用与参考文献格式采用哪一套（以及从哪拿到样式文件）。**去哪查**：课程要求或接收方说明（链接待补）。
- [ ] **要填什么**：作者署名规则（谁算作者、顺序怎么定、通讯作者怎么标、贡献声明与致谢怎么写、顺序变化如何处理）。**去哪查**：导师、课题组惯例与接收方要求（链接待补）。
- [ ] **要填什么**：资助信息与利益冲突声明的写法与要求。**去哪查**：接收方要求与导师（链接待补）。
- [ ] **要填什么**：AI 工具在写作与代码中的允许范围与必须声明的方式。**去哪查**：课程规定与接收方政策（链接待补）。
- [ ] **要填什么**：查重或相似度检查的规则与提交前自查方式。**去哪查**：课程或接收方说明（链接待补）。
- [ ] **要填什么**：数据与代码的公开要求（是否必须、放在哪、以什么许可）。**去哪查**：接收方要求与导师（链接待补）。
- [ ] **要填什么**：提交渠道与流程（系统、邮箱还是纸质），以及提交材料的完整清单。**去哪查**：接收方的提交说明（链接待补）。
- [ ] **要填什么**：投稿前的内审或预答辩等组内惯例（有没有、由谁组织）。**去哪查**：导师与课题组（链接待补）。
- [ ] **要填什么**：预印本能否发布、什么时候能发布、是否需要事先征得同意。**去哪查**：导师与接收方要求（链接待补）。
- [ ] **要填什么**：评审意见的回应方式与时限，以及组内对回复信格式的惯例。**去哪查**：接收方说明与导师（链接待补）。
- [ ] **要填什么**：涉及费用的事项（版面费、彩图费、开放获取费用）与报销渠道。**去哪查**：接收方说明与院系经费管理渠道（链接待补）。
- [ ] **要填什么**：本科生或研究生的成果在评奖、保研、毕业要求中如何被认定。**去哪查**：院系当年的评价办法与教务（链接待补）。
- [ ] **要填什么**：课题组内部的数据管理规则（数据放哪、谁能访问、毕业后怎么交接）。**去哪查**：导师与课题组（链接待补）。
- [ ] **要填什么**：遇到争议（署名、数据归属、评审不公）时的正式沟通与申诉渠道。**去哪查**：导师、院系与研究诚信相关的正式渠道（链接待补）。

:::caution[填写时的三条纪律]
1. **注明适用条件**（年份、方向、课程或接收方类型），没注明的条目读者无法判断是否适用。
2. **区分"文件写的"和"我经历的"**：前者写文件和年份，后者写"某年某方向个人经历"。
3. **不确定就留着不填**。留空比写错安全得多——尤其是署名与规范类条目。
:::

## 怎么自己找信息

| 渠道 | 能得到什么 | 注意事项 |
| --- | --- | --- |
| **正式要求文件** | 格式、篇幅、规范、提交方式的唯一权威口径 | 以当次正式版本为准，不要用去年的模板 |
| **导师与课题组** | 署名惯例、投稿节奏、内审流程、数据管理规则 | 组与组之间差别很大，换组就要重新问 |
| **同方向的亲历者** | 真实的耗时、卡点、被退回来的原因 | 一个人不等于普遍情况，至少问两三个人 |

校内门户与图书馆是查正式说明与文献的入口（[信息门户](https://info.tsinghua.edu.cn/)、[图书馆](https://lib.tsinghua.edu.cn/)）；方法类公开资料可以看 [Missing Semester（中文版）](https://missing-semester-cn.github.io/)、[CS 自学指南](https://csdiy.wiki/)、[清华大学计算机系学生科协技能引导文档](https://docs.net9.org/)、[软件学院 ReadMe 互助文档](https://ssast-readme.github.io/)、[未央书院学习资料](https://weiyangxuexi.github.io/)。这些站点由学生维护，**不代表学校或任何接收方的口径，也可能过期**——用它们了解"有哪些选项"，用正式文件确认"这次是什么要求"。

## 常见误解

以下几条**不依赖任何具体政策**，所以可以放心写：

1. **以为要"读完全部相关论文"，第一轮就要读懂每个公式。** 真正的动作是**收敛**：用综述和几篇代表作搞清术语与主要分歧，再只精读与你的问题直接相关的那几篇；不懂的地方记下来，等真要复现时再回去啃。
2. **以为结果对不上就是自己的错。** 环境、数据版本、随机性都可能造成差异。**记录差异、如实报告，比强行对齐数字重要得多。**
3. **以为写作是最后一步。** 图表和"一句话贡献"应该在动手前就想清楚；**写到一半才发现贡献不成立，是最常见的时间黑洞**。
4. **以为署名和规则"到时候再说"。** 署名顺序、数据归属、AI 使用范围**必须提前问清**，事后补讨论最伤合作。
